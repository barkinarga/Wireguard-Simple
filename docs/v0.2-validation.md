# v0.2 validation — 28 October 2026

## Completed locally

- TypeScript checks and the embedded interface build passed.
- Seven localization tests passed, covering all 329 messages in 10 languages, matching interpolation fields, English defaults, unavailable/corrupt storage, saved preferences, RTL reset, literal user data, current/legacy server events, and the script size budget.
- The existing Go backend tests and `go vet` passed on Windows. Windows temporary-directory access restrictions were resolved by using a workspace-local test temporary directory; no system permissions were changed.
- Browser checks showed all 10 languages on desktop and at 375×812, without page-wide horizontal overflow. German persisted after reload; Arabic switched the document to RTL and returned to LTR after selecting English.
- Unsaved storage settings (budget, checkbox, sampling interval) survived language changes. A read-only local setup/login fixture confirmed language selection before authentication and visually preserved a sample username. No account was created or credential changed during this fixture test.
- Arabic mobile menu navigation reached the storage page without overflow. Dates, relative times, translated labels, and event text rendered in the selected languages.
- New English desktop/mobile screenshots contain only generated demo data. The preview used loopback-only demo mode and did not install WireGuard or change Windows networking.
- Mocked installer tests passed for all seven distribution IDs, apt/dnf plans, EL yum fallback, unsupported/retired platform rejection, read-only check and no-deps, repository failure without enabling repos, preserving an existing curl provider, kernel dry-run, and exact-path `restorecon` calls.
- Existing isolated installer scenarios passed: architecture/ELF checks, new installation, configuration-preserving upgrade, no-start, and failed-start rollback. Native symlink creation was unavailable in the Windows Bash test; Linux CI exercises that scenario.

## CI coverage

Linux CI builds the interface and all application targets, runs localization tests, Go race tests, vet, isolated installer scenarios, distribution mocks, and package integrity checks. Package resolution jobs use isolated Debian 13, Ubuntu 24.04, Rocky Linux 9, AlmaLinux 9, CentOS Stream 9 and Fedora 43 containers with their real package managers. They install tools only; they do not use privileged containers, start systemd services, change host networking, or exercise a real VPN. Publication waits for the build and package-resolution jobs to succeed.

RHEL repository/subscription access is not available in this environment. Its package-manager branch is covered by mocks and follows the vendor's documented package names; it is not equivalent to a real subscribed RHEL installation test.

## Still requiring target-server validation

Actual systemd service startup, kernel WireGuard operations, real client connectivity, routing/NAT, SELinux enforcement, custom firewalld policies, reboot recovery, EL8 custom modules, ARM64 distribution installs, disk pressure and long-running resource measurements remain unverified on real target servers. Container package tests do not establish those properties. Installer support must not be described as production certification.
